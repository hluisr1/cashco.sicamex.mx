1. Resumen Ejecutivo

Este documento describe el prototipo del sistema SICAMEX (Sistema de Control y Administración de Mercancías), desarrollado como una solución ligera para visualizar y entender la funcionalidad del sistema original sin necesidad de instalar dependencias complejas o configurar bases de datos.

El prototipo está construido completamente en tecnologías web estándar (HTML5, CSS3, JavaScript ES6+) y utiliza un archivo JSON como fuente de datos, lo que permite su ejecución inmediata en cualquier navegador moderno.

✅ Objetivo Cumplido: Visualización completa de la funcionalidad del sistema con datos de prueba realistas basados en la estructura real del código fuente original (fWS.asmx.cs y clases DAO).

4. Estructura de Datos

4.1 Entidades Principales

El prototipo maneja las siguientes entidades basadas en las clases DAO del sistema original:

  • Cedis: Centros de distribución (id, Nombre, Latitud, Longitud, nEmpresa, RFC, Telefono, Domicilio)
  • TipoUsuario: Roles del sistema (id, Nombre, Auth, Descripcion)
  • Usuarios: Usuarios del sistema (Nickname, idCedis, idTipo, Nombre, Apellidos, Celular, Email, etc.)
  • Marcas: Marcas de productos (id, Nombre)
  • Grupos: Categorías de productos (id, Nombre)
  • Productos: Catálogo completo (id, idMarca, idGrupo, Nombre, Precio, Codigo, Cargas, Ventas, Inventario)
  • Clientes: Base de clientes (id, idCedis, NombreTienda, Nombre, Apellidos, Celular, Correo, Latitud, Longitud, Activo)
  • Rutas: Rutas de reparto (id, idCedis, idTipoRuta, Nombre, TipoRuta)
  • VisitasCliente: Registro de visitas (id, idRuta, idCliente, idUsuario, Fecha, Estatus)
  • EntregaProducto: Detalle de entregas (idDetalleVisita, idProducto, Cantidad, Total, idPromocion, etc.)
  • CausaDevolucion: Catálogo de causas (id, Nombre)
  • Devoluciones: Registro de devoluciones (id, idDetalleVisita, idProducto, idCausaDevolucion, Cantidad, Total, nAutorizacion)
  • Indicadores: Métricas de gestión (Concepto, Valor, Meta, Porcentaje)
⚠️ Nota Importante: En el prototipo, los datos están almacenados en un archivo JSON plano. En el sistema original, esta información reside en una base de datos MySQL y se accede mediante WebServices (fWS.asmx.cs) que ejecutan Stored Procedures.

5. Arquitectura Técnica

5.1 Stack Tecnológico del Prototipo

  • Frontend: HTML5, CSS3, JavaScript ES6+
  • Librerías: Chart.js (para gráficas)
  • Datos: JSON file (database.json)
  • Servidor: HTTP Server básico (Python, Node.js, o cualquier servidor estático)

5.2 Arquitectura del Sistema Original

  • Backend: ASP.NET WebForms (.aspx) + WebServices (.asmx)
  • Lenguaje: C#
  • Base de Datos: MySQL
  • Acceso a Datos: MySql.Data.MySqlClient + Stored Procedures
  • DAO: 68+ clases en carpeta /DAO
  • Empresas Soportadas: SICAMEX, BYDSA, CASH, ONTIME

5.3 WebServices Principales (fWS.asmx.cs)

El sistema original cuenta con 294 WebMethods que gestionan todas las operaciones. Los más relevantes son:

  • i_Cedis, s_Cedis, u_Cedis, d_Cedis - CRUD de CEDIS
  • i_TipoUsuario, s_TipoUsuario - Gestión de tipos de usuario
  • i_Usuario, s_Usuario, u_Usuario - Gestión de usuarios
  • i_Producto, s_Producto, u_Producto - Gestión de productos
  • i_Cliente, s_Cliente - Gestión de clientes
  • s_VentaDiaRuta, s_VentaAcumulada - Reportes de ventas
  • i_Devolucion, s_Devolucion - Gestión de devoluciones

6. Recomendaciones de Mejora

🔧 Mejoras Técnicas Prioritarias

  1. Validación de Datos: Implementar validación del lado del cliente y servidor para todos los formularios
  2. Autenticación: Añadir sistema de login con roles y permisos basados en el campo "Auth"
  3. Paginación: Implementar paginación en tablas con grandes volúmenes de datos
  4. Búsqueda y Filtrado: Añadir funcionalidad de búsqueda en tiempo real y filtros avanzados
  5. Responsive: Optimizar para dispositivos móviles (actualmente es parcialmente responsive)

📊 Mejoras de Funcionalidad

  1. CRUD Completo: Implementar operaciones reales de Crear, Editar y Eliminar (actualmente solo lectura)
  2. Stock en Tiempo Real: Actualizar inventarios después de cada entrega
  3. Reportes Avanzados: Generar reportes PDF/Excel con más métricas
  4. Geolocalización: Mostrar mapas con ubicación de clientes y rutas
  5. Notificaciones: Alertas de stock bajo, devoluciones pendientes, etc.

🗄️ Mejoras de Arquitectura

  1. Backend Real: Migrar a API REST con Node.js/Express o Python/FastAPI
  2. Base de Datos: Implementar PostgreSQL o MySQL con esquema normalizado
  3. ORM: Usar Sequelize, TypeORM o SQLAlchemy para acceso a datos
  4. Framework Frontend: Migrar a React, Vue o Angular para mejor mantenibilidad
  5. Testing: Implementar pruebas unitarias y de integración
